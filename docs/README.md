## Источники истины

Код определяет **как работает сейчас**. Требование со статусом «предложено» описывает **как рекомендуется сделать**, но не считается принятым владельцем игровым правилом. Спецификация принятой задачи определяет **что менять**. ADR объясняет **почему**. Update фиксирует **что действительно сделано**. При конфликте документировать расхождение, а не молча приводить игру к любому найденному тексту.

У требований стабильные ID `REQ-*`, у замечаний ревью `REVIEW-*`. Связь задачи: `spec → REQ → код → проверка → update`. Не копировать целые требования в каждый документ: использовать ссылки и ID. Баланс и жизненный цикл описываются в project/requirements, карта файлов — в project-map, причины решений — в ADR.
