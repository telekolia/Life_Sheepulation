# 2026-10-11 — питание падальщика

## Результат

Реализовано и проверено в пределах согласованного исправления scavenger.py:
выбранный объект передаётся прямо в `_eat_food`, без повторного поиска по
координатам. Мёртвый труп с ненулевым ID даёт +20 сытости до максимума и
помечается id=0; повторно он не кормит. Поиск пропускает id=0, получение
цели через `.get()` не вызывает KeyError при отсутствии записи.

Удаление владельцем повторного `_define_target` и исправление условия с
запятой сохранены. Поиск цели выполняется один раз за вызов голодного поведения.

## Связи и изменения

REQ-FOOD-03, частично REQ-LIFE-07; REVIEW-01 и повторный поиск из REVIEW-02.
Минимальный план: передавать выбранный труп, исключить pending deletion,
проверить питание и границы, обновить требования и эту запись.
Изменены scavenger.py и требования; добавлены tests/test_scavenger.py.
Внутренняя сигнатура `_eat_food(entity, corpse)` заменяет старую
`_eat_food(entity, food_pos, entities)`.

## Проверка

Из корня: `.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v`.
Python 3.13.7, Pygame 2.6.1: 7 тестов, OK.

Проверены: два падальщика и один труп в одном ходе; потребление конкретного
объекта при совпадающих координатах; отказ для живого объекта, тайла,
id=0, None и объекта без Position; ограничение сытости; выбор доступного
трупа вместо уже съеденного; отсутствующая прежняя цель; отказ от еды
на расстоянии больше 1. Решение случайного блуждания фиксировано в тестах.
Проверка не открывает настоящее окно: интерфейс не менялся.
Окружение печатает предупреждение о расположении Python, но тесты завершаются успешно.
